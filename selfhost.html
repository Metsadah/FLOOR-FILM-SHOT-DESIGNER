Run it yourself

Your server, your data,
the whole app.

Floorboard is a folder of static files: HTML, CSS and JavaScript, no build step and no server code of its own. Hosting it yourself means putting that folder behind a web server. Ten minutes for the local version, half an hour with accounts and sync.

License. Floorboard is source-available under the Elastic License 2.0. Running it for yourself, your crew or your company — paid productions included — is allowed and encouraged. Offering Floorboard itself as a hosted or managed service to others is not.

Which version do you want?

Both versions have every floor, every export and the iPad layout. Start local; switching to cloud later is a two-line change in one file.

Ten minutes

1 · The local version

1

Get the folder

Download the release zip and unpack it, or clone the repository. Everything the app needs is inside; nothing has to be installed.

floorboard/
index.html
landing.html · selfhost.html · news.html
config.js ← the only file you edit
js/ · icons/ · setup/ · tokens.css · styles.css
manifest.json · service-worker.js
2

Leave the keys empty

Open config.js. Two empty strings mean: local mode, no accounts, work stays in this browser.

// config.js
window.FLOOR_CONFIG = {
  supabaseUrl: '',
  supabaseKey: '',
  // billing stays off: every feature unlocked
};
3

Serve it over http

Any static server works. Opening index.html straight from disk mostly works too, but offline mode and “install as app” need http(s).

  • Python: one line, good for trying it out.
  • Docker: the included Dockerfile or plain nginx.
  • Or drop the folder on Netlify, Cloudflare Pages, GitHub Pages.
# on a Mac or Linux machine with Python
python3 -m http.server 8080

# or with Docker (nginx)
docker run -d -p 8080:80 \
  -v "$PWD":/usr/share/nginx/html:ro nginx:alpine

# or the included Dockerfile
docker build -t floorboard . && docker run -d -p 8080:80 floorboard
4

Open it, install it

Go to http://localhost:8080. From the browser menu you can install it as an app; it then works offline.

Where is my work? In the browser profile that made it. Clearing site data deletes it — export a .floorproj (Production ▾) before you clean up or move machines. That one file holds everything, images included.

2 · The cloud version

You bring the database; Floorboard talks to it directly from the browser. Supabase is what the app is built for and its free tier is enough for a small company.

1

Create a Supabase project

Sign up at supabase.com, New project, pick a region near you, choose a strong database password (you will not need it in Floorboard). Wait until the project shows “Active”.

5

Deploy the folder

Any static host: Netlify, Cloudflare Pages, GitHub Pages, Vercel, or your own nginx / Apache. No server settings beyond serving the files; https is required for sign-in.

Then open the site and sign in with your e-mail. The first account is created on the spot.

# Netlify CLI, for example
npx netlify deploy --prod --dir=.

# or nginx: serve the folder, nothing else
server {
  listen 443 ssl;
  server_name floorboard.yourcompany.com;
  root /srv/floorboard;
  index index.html;
}
6

Recommended: your own mail sender

Authentication → Emails → SMTP settings. Without it, sign-in mails come from Supabase’s shared sender with a very low hourly limit — fine for you alone, not for a crew signing up on the same afternoon. Any SMTP provider works (Resend, Postmark, Mailgun, your own).

  • Backups: daily on paid Supabase plans; on the free plan export the database now and then, or rely on .floorproj exports.
  • Plan gates are off in a self-hosted copy: everything is unlocked. See BILLING.md only if you want to sell access yourself.

3 · Updating

Replace the files

Every file except config.js. Reload the page; the version chip top right shows the new number. Hard-reload once if it does not: the offline cache hands over on the second load.

Database changes

Ordinary updates need nothing. When a release adds tables or columns, the notes at the end of setup/schema.sql say what to run — each statement is written so running it twice is harmless.

iPad app

The iPad app is a shell around the same files. Self-hosters point it at their own copy in config.ios.js and build it with Xcode; see IPAD.md.

4 · People and access

Inviting. Share → People on this production: name, email, co-edit or read-only, and a tick per floor. With an email the person is joined the moment they sign in with that address; the link is a shortcut. Read-only people browse and export, the database refuses their writes. Needs setup/invites-v2.sql (part of schema.sql §7 for fresh installs).

One account per person

Everyone signs in with their own e-mail; productions belong to the account that created them.

Co-editing with floor access

The owner enables it per production (Share → Co-editors) and hands out invite links: all floors, or crew — mood, script, plans and shot list, but not Budget and Production. Per member, the owner switches floors on or off with the chips next to their name.

Read-only links & Floor Scanner

Share links show a frozen copy to anyone with the link; viewers can drop comment pins, nothing else. Floor Scanner on iPhone signs in with the same account; scanned rooms and location photos appear in the room library.

5 · Troubleshooting

The sign-in mail never arrives

Check Supabase → Authentication → Logs, and the hourly limit of the built-in sender. Set up SMTP (step 6); that removes the limit.

“Invalid redirect” after clicking the mail link

The address you host on is missing from Redirect URLs (step 4). Add it with a trailing /** to cover every page.

Works locally, not on the server

The app is served over plain http (sign-in needs https), or the folder is served from a sub-path while the Site URL points elsewhere. The app itself is path-independent; sign-in is not.

A colleague sees no productions

They are signed in with a different e-mail than the invite was sent to, or the invite was revoked. Send a fresh invite link from Share → Co-editors.

The version chip does not change after an update

Hard-reload once; the offline cache hands over on the second load. On iPad, remove and re-add the home-screen app if it insists.

How many people can use one Supabase project?

The free tier allows 50,000 monthly active users, 500 MB of database and 1 GB of file storage — far beyond a production company. Two things to know: a free project pauses after a week without traffic (reopen it in the dashboard), and Floor Scanner photos count toward the file storage. The paid plan removes the pause, adds daily backups and more storage.
